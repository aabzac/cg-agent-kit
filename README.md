# cg-agent-kit

Общие правила и скиллы для проектов CodinGame в Cursor, Codex и Claude Code.
Исходники редактируются здесь один раз; скрипт переносит их в каждый подключённый
репозиторий контеста и фиксирует точную версию набора.

## Что входит

| Исходник | Назначение |
| --- | --- |
| `rules/common.md` | Общие правила работы над ботами и экспериментами |
| `skills/cg-bot-contest/` | Ведение контеста: этапы, инфраструктура, договорённости, цикл усиления бота |
| `skills/cg-fetch-replays/` | Таблицы лидеров и реплеи CodinGame, разбор кадров, захват игр IDE и босса |
| `skills/cg-promote-bot/` | Продвижение: proxy, репликация, проверка регресса, повторные arena uploads и откат |
| `skills/cg-compare-bots/` | Сравнение версий на одинаковых сценариях и со сменой сторон |
| `skills/cg-validate-simulator/` | Проверка симулятора по правилам и эталонным трассам |
| `skills/cg-profile-bot/` | Измерение времени работы и поиск узких мест |
| `templates/project.md` | Шаблон особенностей конкретного контеста |
| `scripts/sync.py` | Подключение, обновление, проверка и запуск агента |

Требуются **Python 3.10+** и **Git** в `PATH`. Дополнительных Python-пакетов нет.
Команды ниже выполняются из PowerShell; те же команды с `/` в путях подходят для
Linux и macOS, где вместо `python` может понадобиться `python3`.

## Подключить контест

Клонируйте набор рядом с репозиториями контестов, если его ещё нет локально:

```powershell
git clone https://github.com/aabzac/cg-agent-kit.git
cd cg-agent-kit
```

Из каталога `cg-agent-kit` подключите существующий репозиторий, заменив `contest`
его именем:

```powershell
python scripts/sync.py init ../contest --source . --repo https://github.com/aabzac/cg-agent-kit.git
```

По умолчанию набор готовит файлы для Claude Code и Codex. Если нужен только один
агент, добавьте `--agents claude` или `--agents codex`. Cursor читает оба каталога
скиллов, поэтому ему подходит любой вариант; при обоих он может показывать дубликаты.

В контесте появятся:

| Файл или каталог | В Git | Как поддерживается |
| --- | --- | --- |
| `.ai/project.md` | да | Редактируется в контесте: правила игры, команды, лимиты и текущие договорённости |
| `.ai/kit.json` | да | Адрес набора, ветка или тег, режим обновления, агенты и хранение скиллов |
| `.ai/kit.lock.json` | да | Точный commit набора и контрольные суммы сгенерированных файлов |
| `.ai/sync.py` | да | Копия скрипта; позволяет обновляться без отдельного клона набора |
| `AGENTS.md` | да | Генерируется из общих правил и `.ai/project.md` |
| `CLAUDE.md` | да | Импортирует `AGENTS.md` через `@AGENTS.md`; создаётся для `claude` |
| `.gitignore` | да | Скрипт меняет только блок между `# BEGIN cg-agent-kit` и `# END cg-agent-kit` |
| `.claude/skills/` | нет | Скиллы набора для Claude Code (`claude`) |
| `.agents/skills/` | нет | Те же скиллы для Codex (`codex`) |

Копии скиллов набора не коммитятся: блок в `.gitignore` скрывает содержимое
папок скиллов выбранных агентов (`/.claude/skills/*`, `/.agents/skills/*`) и не
меняется при обновлениях набора. Собственный скилл, положенный в эти папки, Git
тоже не увидит. Версию скиллов фиксирует `.ai/kit.lock.json`. После клонирования, на другой машине или в новом worktree
выполните `python .ai/sync.py sync .` (или запускайте агента через `run`): скрипт
восстановит копии из закреплённого commit набора.

Заполните `.ai/project.md`, затем из каталога контеста выполните:

```powershell
python .ai/sync.py sync . --source ../cg-agent-kit
python .ai/sync.py check . --source ../cg-agent-kit
```

Коммитьте `.ai/`, `AGENTS.md`, `CLAUDE.md` и `.gitignore` вместе с изменениями
проекта. Не редактируйте сгенерированные файлы напрямую: общие изменения вносите
в этот набор, а особенности контеста — в `.ai/project.md`.

Если скиллы должны лежать в самом репозитории контеста (например, его открывают
там, где нельзя выполнить `sync`), подключите контест с `--commit-skills`. Тогда
блок в `.gitignore` не создаётся, и каталоги скиллов коммитятся вместе с проектом.
Так же работают контесты, подключённые до появления этих настроек: в их
`.ai/kit.json` нет ключей `agents` и `commit_skills`, поэтому генерируются оба
каталога скиллов. Опции `--agents` и `--commit-skills` понимает только `sync.py`,
в котором они уже есть; `init --ref` на более старый commit набора их не примет.

### Агенты и хранение скиллов

Например, с `--agents claude` новый контест получает в `.ai/kit.json`:

```json
{
  "agents": ["claude"],
  "commit_skills": false
}
```

Чтобы поменять агентов или способ хранения, отредактируйте эти ключи и выполните
`python .ai/sync.py sync .`. Скрипт удалит неизменённые копии для убранного
агента, а блок в `.gitignore` обновит или, при `"commit_skills": true`, удалит.

Если скиллы раньше коммитились, после перехода на `"commit_skills": false`
уберите их из индекса Git и закоммитьте это изменение. Файлы останутся на диске:

```powershell
git rm -r --cached --quiet --ignore-unmatch .agents/skills .claude/skills
```

Собственный скилл контеста в этих папках можно вернуть в Git строкой после
блока, например `!/.claude/skills/my-skill/`.

Сессии Claude Code в отдельном worktree, например параллельные сессии в
приложении, начиная с Claude Code 2.1.277 берут скиллы из основной копии, если в
worktree нет каталога `.claude/skills`. При игнорируемых папках его там нет. Если
вы вернули в Git собственный скилл, каталог появится; тогда добавьте строку
`.claude/skills/` в файл `.worktreeinclude` в корне контеста, и Claude Code
скопирует игнорируемые копии в новый worktree. Для Codex и Cursor выполните в
worktree `python .ai/sync.py sync .`.

### Если инструкции уже есть

`init` сохраняет существующий `.ai/project.md`, но не перезаписывает существующие
`AGENTS.md`, `CLAUDE.md` и файлы скиллов с совпадающими путями. При конфликте он
завершается до записи файлов.

Перед миграцией сохраните исходные инструкции в Git или отдельной резервной копии.
Перенесите нужные правила контеста из старых `AGENTS.md` и `CLAUDE.md` в
`.ai/project.md`, проверьте результат и только затем удалите старые файлы и
повторите `init`. Для совпадающих скиллов сначала сохраните их изменения в
подходящем исходнике либо переименуйте проектный скилл. Другие скиллы и настройки
агентов скрипт сохраняет. Вложенные инструкции и `.cursor/rules/` остаются
действующими — проверьте, что они не противоречат общим правилам.

## Обновление и воспроизводимость

Эти команды выполняются **из каталога контеста**:

```powershell
python .ai/sync.py update .
python .ai/sync.py sync .
python .ai/sync.py check .
```

| Команда | Действие |
| --- | --- |
| `update` | Получает текущий commit ветки/тега из `kit.json`, обновляет файлы и lock |
| `sync` | Пересобирает файлы из commit, уже записанного в lock; учитывает изменения `.ai/project.md` и `.ai/kit.json` |
| `check` | Проверяет результат по зафиксированному commit и текущим `.ai/project.md` и `.ai/kit.json`; не меняет файлы контеста |

Без `--source` скрипт получает исходники из Git-адреса в `kit.json` во временный
каталог (если указан локальный путь, читает его напрямую). Поэтому даже `sync`
и `check` требуют доступа к этому репозиторию.
Для работы без сети добавьте `--source ../cg-agent-kit`: нужный commit должен
присутствовать в локальном клоне. Скрипт читает **закоммиченную версию** и сообщает,
если игнорирует незакоммиченные изменения исходников. Он не переключает ветки
и не изменяет рабочую копию набора. Для получения свежих изменений в локальный
клон отдельно выполните `git pull --ff-only` в каталоге набора.

Каждую операцию, включая запуск команды в `run`, выполняет `sync.py` из применяемого
commit набора. Если запущенная копия отличается от него (например, старый
`.ai/sync.py` во время `update`), она передаёт работу закоммиченной версии и сообщает
об этом. Поэтому новые правила генерации и запуска действуют с первого же вызова,
а `check` сверяет файлы той же версией.

По умолчанию `.ai/kit.json` нового контеста содержит:

```json
{
  "agents": ["claude", "codex"],
  "commit_skills": false,
  "ref": "master",
  "repository": "https://github.com/aabzac/cg-agent-kit.git",
  "schema_version": 1,
  "update": "tracking"
}
```

Для завершённого контеста измените `update` на `pinned` или используйте `--pinned`
при `init`. Режим `pinned` запрещает автоматическое обновление при `run`, но
**явная команда `update` всё равно обновляет набор**. `sync` и `check` всегда
используют lock независимо от режима. `ref` можно заменить тегом релиза.

Если сгенерированный файл изменён вручную, скрипт останавливается и перечисляет
конфликты. Перенесите и сохраните эти правки в исходнике. Если конфликт остаётся,
восстановите только соответствующую сгенерированную копию из Git и повторите
синхронизацию; не восстанавливайте исходник с нужными правками. Удаляются
только ранее учтённые файлы набора, исчезнувшие в новой версии; неизвестные файлы
не удаляются.

## Автоматически обновлять перед запуском

Из каталога контеста запускайте установленный CLI агента через обёртку:

```powershell
python .ai/sync.py run . -- codex
python .ai/sync.py run . -- claude
```

`run` сначала выполняет `update` для режима `tracking` или `sync` для `pinned`,
затем запускает указанную команду в каталоге контеста. На Windows команда ищется
по `PATH` и `PATHEXT`, как в PowerShell, поэтому подходят и npm-обёртки вроде
`codex.cmd`. Аргументы таких `.cmd` и `.bat` экранируются для `cmd.exe`: символы
`& | < > ^ % !` и кавычки доходят до агента как есть, а переводы строк в аргументах
запрещены. Ошибка синхронизации останавливает запуск. Для локального источника:

```powershell
python .ai/sync.py run . --source ../cg-agent-kit -- codex
```

Это автоматизация только для запусков через обёртку. При работе через интерфейс
(приложение Claude, Cursor или Codex) выполните `update` перед новым диалогом. Уже
открытый диалог может сохранять прежние инструкции. Скрипт не устанавливает глобальные hooks
и не запускает фоновое обновление других проектов.

## Проверка в CI контеста

Минимальный шаг после checkout и установки Python:

```yaml
- name: Check shared agent instructions
  run: python .ai/sync.py check .
```

Проверка использует commit из lock, поэтому новый commit в `master` набора сам по
себе не меняет результат проверки старого контеста. Если скиллы не коммитятся,
на чистом checkout их копий нет, и `check` это допускает: он сверяет `AGENTS.md`,
`CLAUDE.md`, `.ai/sync.py`, lock и блок в `.gitignore`. Если копии есть хотя бы
частично, они должны совпадать полностью. Для приватного набора CI
нужна авторизация Git с доступом к нему; стандартного токена другого репозитория
может быть недостаточно. Альтернатива — отдельно получить нужную версию набора
и передать её через `--source`.

Обновление контестов через отдельные PR можно добавить позже. Сейчас здесь нет
расписания, автоматически изменяющего другие репозитории.

## Изменить общий набор

1. Измените `rules/common.md` или соответствующий каталог `skills/`.
2. Выполните проверки из корня этого репозитория:

   ```powershell
   python scripts/validate.py
   python -m unittest discover -s tests -v
   ```

   `validate.py` применяет к рабочей копии, включая ещё не добавленные в Git файлы,
   те же правила путей, что и `sync.py`. Например, файл прямо в `skills/` или
   каталог скилла без `SKILL.md` остановили бы `update` во всех контестах. Тесты
   также подключают закоммиченный `HEAD` набора к временному контесту.

3. Закоммитьте изменения и отправьте их на GitHub. Контесты в режиме `tracking`
   получат их при следующем `run`, поэтому проверки должны пройти до push.
4. В нужных контестах выполните `update`, проверьте diff и закоммитьте результат.

CI набора запускает проверки на Windows и Ubuntu с Python 3.10 и 3.14.

## Что перенесено из Back Track King

Обновление методики основано на документах контеста
[`summer-challenge-2026-back-track-king`](https://github.com/aabzac/summer-challenge-2026-back-track-king/tree/56a6624baeda1965ada7e8e6e62eaa20eee97d17),
ветка `master`, коммит `56a6624` от 28.10.2026: `benchmarking-v5.md`, `arena-uploads.md`,
`boss-v4.md`, `repo-cleanup-v1.md`, `prune-v1.md` и `cold-timing-30x20-v1.md` в `docs/`.

- В `cg-promote-bot` перенесён порядок «screen → свежая репликация → защита от
  регресса → live-фильтр → повторные размещения на арене → продвижение или откат».
  Политика от 27.10.2026 позволяет продвижение при отсутствии явно худшего
  результата после всех проверок; это практическое правило, не доказательство превосходства.
- Результаты на арене сравниваются только внутри одной лиги: после повышения baseline
  выбранной версии собирается заново. За каждым upload нужно следить до конца placement:
  повышение в лиге в конце placement заменяет агента, и список его игр пропадает.
- Точные пороги BTK, первая калибровка шума и открытые вопросы вынесены в
  [отдельный профиль](skills/cg-promote-bot/references/back-track-king-policy.md).
  Baseline v13 в Gold — 10.82 и 10.65, M ≈ 1.0 по одной паре загрузок в Silver и одной
  в Gold. Это предварительная оценка, а не проверенная константа.
- [practical-300-1000-v2](skills/cg-promote-bot/references/practical-300-1000.md) —
  сентябрьская политика того же контеста, которую он потом заменил версиями v3–v5.
  Она сохранена как отдельная альтернатива для проектов, которые явно приняли её.
- Дополнены сохранение игр перед заменой live agent и восстановление потерянных
  результатов, учёт отдельных uploads, проверка холодного процесса и объёма поиска даже
  без таймаутов, удаление закрытых экспериментов с сохранением нужных тестов и
  доказательств, архивирование журналов.

Настройки конкретного проекта задаются в `.ai/project.md`; шаблон содержит поля для
этапов продвижения, повторных uploads, лиг, калибровки шума и правил отката.
Исходный контест при переносе не изменялся. Команды, Java-реализация, лимиты и
численные пороги этого контеста не назначаются универсальными настройками CG.

## Совместимость

Схема рассчитана на агентов, работающих с файлами репозитория. Она не устанавливает
личные скиллы в обычный ChatGPT или claude.ai. Cursor также читает
`.claude/skills/`; при обоих агентах копии одинаковы, но отображение дубликатов
в меню зависит от клиента, поэтому для Cursor достаточно одного каталога (`agents`).
Для Windows используются обычные файлы, без symlink.
Скрипт переносит содержимое файлов, но не Unix-бит исполняемости. Если добавляете
к скиллам скрипты, вызывайте их через интерпретатор: `python script.py` или
`bash script.sh`.

Файлы набора копируются побайтно. Git с `core.autocrlf=true` (по умолчанию в Git for
Windows) при checkout добавляет CR перед LF в текстовых файлах, и это не считается
локальной правкой; текст определяется по содержимому так же, как это делает Git.
Ресурс, в котором важны CRLF (в наборе он помечен `-text`), пометьте так же в
`.gitattributes` контеста. Иначе Git контеста может изменить его переводы строк:
`check` сообщит `line endings differ`, а `sync` восстановит исходные байты.
Контрольные суммы из lock-файлов прежних версий принимаются; при следующем `sync`
lock переписывается в текущем формате.

Подключение основано на официальной документации, проверенной 28.10.2026:

- [Cursor: правила](https://cursor.com/docs/rules) и [скиллы](https://cursor.com/docs/skills).
- [Codex: AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md) и [локальные скиллы](https://learn.chatgpt.com/docs/build-skills).
- [Claude Code: инструкции и импорт](https://code.claude.com/docs/en/memory) и [скиллы](https://code.claude.com/docs/en/skills).
