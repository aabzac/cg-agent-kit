# cg-agent-kit

Общие правила и скиллы для проектов CodinGame в Cursor, Codex и Claude Code.
Исходники редактируются здесь один раз; скрипт переносит их в каждый подключённый
репозиторий контеста и фиксирует точную версию набора.

## Что входит

| Исходник | Назначение |
| --- | --- |
| `rules/common.md` | Общие правила работы над ботами и экспериментами |
| `skills/cg-compare-bots/` | Сравнение версий на одинаковых сценариях и со сменой сторон |
| `skills/cg-validate-simulator/` | Проверка симулятора по правилам и эталонным трассам |
| `skills/cg-profile-bot/` | Измерение времени работы и поиск узких мест |
| `templates/project.md` | Шаблон особенностей конкретного контеста |
| `scripts/sync.py` | Подключение, обновление, проверка и запуск агента |

Требуются **Python 3.10+** и **Git** в `PATH`. Дополнительных Python-пакетов нет.
Команды ниже выполняются из PowerShell; те же команды с `/` в путях подходят для
Linux и macOS, где вместо `python` может понадобиться `python3`.

## Подключить контест

Клонируйте набор рядом с репозиториями контестов, если его ещё нет локально:

```powershell
git clone https://github.com/aabzac/cg-agent-kit.git
cd cg-agent-kit
```

Из каталога `cg-agent-kit` подключите существующий репозиторий, заменив `contest`
его именем:

```powershell
python scripts/sync.py init ../contest --source . --repo https://github.com/aabzac/cg-agent-kit.git
```

В контесте появятся:

| Файл или каталог | Как поддерживается |
| --- | --- |
| `.ai/project.md` | Редактируется в контесте: правила игры, команды, лимиты и текущие договорённости |
| `.ai/kit.json` | Адрес набора, ветка или тег и режим обновления |
| `.ai/kit.lock.json` | Точный commit набора и контрольные суммы сгенерированных файлов |
| `.ai/sync.py` | Копия скрипта; позволяет обновляться без отдельного клона набора |
| `AGENTS.md` | Генерируется из общих правил и `.ai/project.md` |
| `CLAUDE.md` | Импортирует `AGENTS.md` через `@AGENTS.md` |
| `.agents/skills/` | Сгенерированные скиллы для Codex и Cursor |
| `.claude/skills/` | Те же скиллы для Claude Code |

Заполните `.ai/project.md`, затем из каталога контеста выполните:

```powershell
python .ai/sync.py sync . --source ../cg-agent-kit
python .ai/sync.py check . --source ../cg-agent-kit
```

Коммитьте `.ai/`, `AGENTS.md`, `CLAUDE.md` и оба каталога скиллов вместе с
изменениями проекта. Тогда инструкции доступны сразу после обычного клонирования.
Не редактируйте сгенерированные файлы напрямую: общие изменения вносите в этот
набор, а особенности контеста — в `.ai/project.md`.

### Если инструкции уже есть

`init` сохраняет существующий `.ai/project.md`, но не перезаписывает существующие
`AGENTS.md`, `CLAUDE.md` и файлы скиллов с совпадающими путями. При конфликте он
завершается до записи файлов.

Перед миграцией сохраните исходные инструкции в Git или отдельной резервной копии.
Перенесите нужные правила контеста из старых `AGENTS.md` и `CLAUDE.md` в
`.ai/project.md`, проверьте результат и только затем удалите старые файлы и
повторите `init`. Для совпадающих скиллов сначала сохраните их изменения в
подходящем исходнике либо переименуйте проектный скилл. Другие скиллы и настройки
агентов скрипт сохраняет. Вложенные инструкции и `.cursor/rules/` остаются
действующими — проверьте, что они не противоречат общим правилам.

## Обновление и воспроизводимость

Эти команды выполняются **из каталога контеста**:

```powershell
python .ai/sync.py update .
python .ai/sync.py sync .
python .ai/sync.py check .
```

| Команда | Действие |
| --- | --- |
| `update` | Получает текущий commit ветки/тега из `kit.json`, обновляет файлы и lock |
| `sync` | Пересобирает файлы из commit, уже записанного в lock; учитывает изменения `.ai/project.md` |
| `check` | Проверяет результат по зафиксированному commit и текущему `.ai/project.md`; не меняет файлы контеста |

Без `--source` скрипт получает исходники из Git-адреса в `kit.json` во временный
каталог (если указан локальный путь, читает его напрямую). Поэтому даже `sync`
и `check` требуют доступа к этому репозиторию.
Для работы без сети добавьте `--source ../cg-agent-kit`: нужный commit должен
присутствовать в локальном клоне. Скрипт читает **закоммиченную версию** и сообщает,
если игнорирует незакоммиченные изменения исходников. Он не переключает ветки
и не изменяет рабочую копию набора. Для получения свежих изменений в локальный
клон отдельно выполните `git pull --ff-only` в каталоге набора.

Каждую операцию, включая запуск команды в `run`, выполняет `sync.py` из применяемого
commit набора. Если запущенная копия отличается от него (например, старый
`.ai/sync.py` во время `update`), она передаёт работу закоммиченной версии и сообщает
об этом. Поэтому новые правила генерации и запуска действуют с первого же вызова,
а `check` сверяет файлы той же версией.

По умолчанию `.ai/kit.json` содержит:

```json
{
  "schema_version": 1,
  "repository": "https://github.com/aabzac/cg-agent-kit.git",
  "ref": "master",
  "update": "tracking"
}
```

Для завершённого контеста измените `update` на `pinned` или используйте `--pinned`
при `init`. Режим `pinned` запрещает автоматическое обновление при `run`, но
**явная команда `update` всё равно обновляет набор**. `sync` и `check` всегда
используют lock независимо от режима. `ref` можно заменить тегом релиза.

Если сгенерированный файл изменён вручную, скрипт останавливается и перечисляет
конфликты. Перенесите и сохраните эти правки в исходнике. Если конфликт остаётся,
восстановите только соответствующую сгенерированную копию из Git и повторите
синхронизацию; не восстанавливайте исходник с нужными правками. Удаляются
только ранее учтённые файлы набора, исчезнувшие в новой версии; неизвестные файлы
не удаляются.

## Автоматически обновлять перед запуском

Из каталога контеста запускайте установленный CLI агента через обёртку:

```powershell
python .ai/sync.py run . -- codex
python .ai/sync.py run . -- claude
```

`run` сначала выполняет `update` для режима `tracking` или `sync` для `pinned`,
затем запускает указанную команду в каталоге контеста. На Windows команда ищется
по `PATH` и `PATHEXT`, как в PowerShell, поэтому подходят и npm-обёртки вроде
`codex.cmd`. Аргументы таких `.cmd` и `.bat` экранируются для `cmd.exe`: символы
`& | < > ^ % !` и кавычки доходят до агента как есть, а переводы строк в аргументах
запрещены. Ошибка синхронизации останавливает запуск. Для локального источника:

```powershell
python .ai/sync.py run . --source ../cg-agent-kit -- codex
```

Это автоматизация только для запусков через обёртку. При работе через интерфейс
Cursor или Codex выполните `update` перед новым диалогом. Уже открытый диалог
может сохранять прежние инструкции. Скрипт не устанавливает глобальные hooks
и не запускает фоновое обновление других проектов.

## Проверка в CI контеста

Минимальный шаг после checkout и установки Python:

```yaml
- name: Check shared agent instructions
  run: python .ai/sync.py check .
```

Проверка использует commit из lock, поэтому новый commit в `master` набора сам по
себе не меняет результат проверки старого контеста. Для приватного набора CI
нужна авторизация Git с доступом к нему; стандартного токена другого репозитория
может быть недостаточно. Альтернатива — отдельно получить нужную версию набора
и передать её через `--source`.

Обновление контестов через отдельные PR можно добавить позже. Сейчас здесь нет
расписания, автоматически изменяющего другие репозитории.

## Изменить общий набор

1. Измените `rules/common.md` или соответствующий каталог `skills/`.
2. Выполните проверки из корня этого репозитория:

   ```powershell
   python scripts/validate.py
   python -m unittest discover -s tests -v
   ```

   `validate.py` применяет к рабочей копии, включая ещё не добавленные в Git файлы,
   те же правила путей, что и `sync.py`. Например, файл прямо в `skills/` или
   каталог скилла без `SKILL.md` остановили бы `update` во всех контестах. Тесты
   также подключают закоммиченный `HEAD` набора к временному контесту.

3. Закоммитьте изменения и отправьте их на GitHub. Контесты в режиме `tracking`
   получат их при следующем `run`, поэтому проверки должны пройти до push.
4. В нужных контестах выполните `update`, проверьте diff и закоммитьте результат.

CI набора запускает проверки на Windows и Ubuntu с Python 3.10 и 3.14.

## Совместимость

Схема рассчитана на агентов, работающих с файлами репозитория. Она не устанавливает
личные скиллы в обычный ChatGPT или claude.ai. Cursor также читает
`.claude/skills/`; обе сгенерированные копии одинаковы, но отображение дубликатов
в меню зависит от клиента. Для Windows используются обычные файлы, без symlink.
Скрипт переносит содержимое файлов, но не Unix-бит исполняемости. Если добавляете
к скиллам скрипты, вызывайте их через интерпретатор: `python script.py` или
`bash script.sh`.

Файлы набора копируются побайтно. Git с `core.autocrlf=true` (по умолчанию в Git for
Windows) при checkout добавляет CR перед LF в текстовых файлах, и это не считается
локальной правкой; текст определяется по содержимому так же, как это делает Git.
Ресурс, в котором важны CRLF (в наборе он помечен `-text`), пометьте так же в
`.gitattributes` контеста. Иначе Git контеста может изменить его переводы строк:
`check` сообщит `line endings differ`, а `sync` восстановит исходные байты.
Контрольные суммы из lock-файлов прежних версий принимаются; при следующем `sync`
lock переписывается в текущем формате.
